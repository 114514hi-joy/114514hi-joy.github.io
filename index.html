为什么做

想有个每天看一眼的东西，但不想被 App 打扰。通知、推送、签到、红点，全都在抢注意力。所以反过来做：一天一次，抽完就没了。

它不需要你回来第二次。第二天再来，是缘分；不来，也不会有“您已连续签到中断”的提示。

怎么做的

整个应用是纯 Java 自定义 View 手绘，没有一个界面用现成控件拼。所以它只有 0.6 MB。

  • 五套界面：卷轴、表盘、卡片、杂志、签筒
  • 五套主题：墨夜、宣纸、青瓷、夜蓝、朱夜
  • 冷启动动画「墨落成签」，2 秒，可点击跳过
  • 月相用真实的月球贴图做正射投影，不是画个月牙
界面截图

踩过的坑

这块手表把 sp 放得比标准大 1.5 倍，`settings.font_scale` 还读出来是 null。12sp 的签文四行就能顶出屏幕，最后给签条套了 ScrollView、字号收一档才稳。

另一个是充电时会弹出系统界面盖住全屏，挡住截图和点击，等 20 秒自动消失。第一次遇到还以为是应用崩了。

一个取舍

八字这类东西，很多人不知道自己几点出生。这个应用的处理是：没时辰就老实算三柱，界面上显示「六字」而不是「八字」。不硬凑，是底线。

墨戏

用代码画墨，用代码出声。没有一张图，没有一段音频。

为什么做

想验证一件事：如果不用任何素材，只靠代码，能不能做出“墨”和“声”的感觉。

结论是能，但要先把“素材”这个词重新理解一遍——噪声函数是素材，振荡器是素材，只是它们不占字节。

墨是怎么出来的

Canvas 逐像素生成，用 value noise 叠 fbm：低频定轮廓，高频出毛刺。像宣纸吸墨，边缘永远是毛的，不会整齐。

关键不在算法，在透明度曲线。第一版墨发灰，我以为是 alpha 太低，调了半天没用。真正的原因是墨滴淡出太快——改成前 55% 的寿命保持全浓，之后才开始渗散，墨才“沉”下来。

签筒交互

声是怎么出来的

没有音频文件，用 Web Audio 现场合成竹签碰撞：噪声爆 → 带通滤波 → 极速衰减。三个节点串起来，三十行代码，随机微调频率和衰减时间，每一下都不完全一样。

3D 签筒

CSS 3D 做的：十一根签用 rotateY 排在圆弧上，再用 translateZ 推到各自的半径，靠 preserve-3d 让浏览器自动处理遮挡关系。

踩的坑是：签的居中用 translate(-50%,-50%)，它和 3D 翻转打架，翻转轴会歪。把 translate 写在 transform 链最前面就好了。

留下来的东西

这套做法后来被我用在了别处：噪点做材质、振荡器做反馈音。素材不是非要去下载，有时候算出来更干净。

为什么做

市面上的命理应用，要么太玄——满屏术语堆砌，说不出人话；要么太糙——输入生日就吐一段星座运势，跟八字没关系。

想做一个中间态：底层算得认真，上层说得克制。

算的是什么

核心是四柱排盘：年柱、月柱、日柱、时柱，每柱天干地支两个字，四柱就是八个字。

  • 十神——正官、七杀、正财、偏财这一类关系
  • 纳音——六十甲子纳音，比如“海中金”“炉中火”
  • 长生十二神——长生、沐浴、冠带、临官……
  • 旬空、三合局、喜忌神
排盘界面

六字与八字

这是我觉得这个应用最诚实的地方。

很多人根本不知道自己几点出生。硬算四柱，时柱就是瞎猜。所以它做了一个判断：有时辰才算八字，没时辰就算三柱，界面上直接显示「六字」。

不是“降级”，是把不确定性摆在明面上。少两个字，就是少两个字的信息量，不能装作一样。

视觉

界面用的是玻璃面板，光影方向跟着手表姿态走。不是贴图，是实时计算——监听传感器，把倾斜方向映射成光照向量，分四层画：色晕、主高光、斜条纹、边缘轮廓。

为了让它在弱芯片上不掉帧，着色器用了阈值缓存：高光中心移动不到半个像素就不重建。人眼分辨不出来的位移，省掉了大半开销。

难在哪

难的不是算法，是规则的数量和流派分歧。十神怎么排、长生怎么起、旬空怎么定，各家讲法不完全一样，写错一个地方整盘就歪。

所以这个应用里每一条结论都能点开看依据——它说的是怎么算出来的，不是“信我”。
