我是寒彻，一名独立开发者。喜欢工具，也喜欢工具里那一点不容易被量化的仪式感。

这些作品大多从自己的需要出发：想在手腕上抽一支签，想听见一段代码发出的声音，想把复杂规则说得清楚。不为了堆功能而做功能，也不拿热闹代替好用。

我相信离线是一种安心，克制是一种礼貌，而真正的精致，往往藏在那些不会被特意注意到的小地方。

不争夺注意力

想有个每天看一眼的东西，但不想被 App 打扰。通知、推送、签到、红点，都在抢注意力。所以反过来做：不催促回来，也不制造中断的愧疚。

第二天再来，是缘分；不来，也不会弹出「连续签到中断」。工具负责解决问题，签负责给普通的一天留一点意味。

为小屏幕而做

整块应用使用纯 Java 自定义 View 绘制。卷轴、表盘、卡片、杂志、签筒与封面六套界面，共用签库、历法、月相与往签记录。

  • 真实月面贴图与正射投影，而不是一枚简单月牙
  • 36 支签、64 卦、节气与农历均在本地计算
  • 378 × 496 真机调校，设计以看清、点准为先
小屏幕不是把桌面界面缩小，
而是重新决定什么值得留下。

踩过的坑

这块手表对 sp 与 dp 的实际换算并不标准，设计稿中的像素不能直接搬进代码。竖排签文也曾被 TextView 的行框切掉，最后改成逐字排列，才把每一个字完整留下。

许多改动不是先在参数里想明白，而是在表上看见问题，再回头重做。这里的精致，来自一次次不太优雅的实测。

CASE 02 · WEB EXPERIMENT / 2026

墨戏

用代码画墨，用代码出声。
没有一张图，也没有一段音频。

交互实验单文件零素材
EVERY DOT, EVERY SOUND.
GENERATED IN REAL TIME.
0图片文件
0音频文件
1HTML 文件

重新理解「素材」

想验证一件事：如果不用任何素材，只靠代码，能不能做出「墨」和「声」的感觉。噪声函数是素材，振荡器也是素材，只是它们不需要被打包。

墨是怎么出来的

Canvas 逐像素生成，用 value noise 叠 fbm：低频决定轮廓，高频制造毛刺。像宣纸吸墨，边缘永远不会过分整齐。

关键不在算法本身，而在透明度曲线。墨滴生命的前 55% 保持全浓，之后才开始渗散，墨色才终于「沉」了下来。

声是怎么出来的

Web Audio 现场合成竹签碰撞：噪声爆、带通滤波、极速衰减。三个节点串起来，再随机微调频率与衰减时间，每一下都不完全相同。

有时候，最干净的素材，
恰好是计算出来的。

一座 CSS 3D 签筒

十一根签用 rotateY 排在圆弧上，再用 translateZ 推到各自的半径，让浏览器处理遮挡。居中的 translate 必须写在 transform 链最前面，否则翻转轴会偏。

底层认真，上层克制

市面上的命理应用，要么满屏术语堆砌，要么输入生日就吐一段与规则无关的运势。这个作品想做一个中间态：保留规则的严谨，也把结论说成人话。

核心包括十神、纳音、长生十二神、旬空、三合局与喜忌神。每一条结论都能继续查看依据，而不是只要求相信。

六字，也是完整答案

很多人不知道自己几点出生。硬算四柱，时柱就是猜测。所以有时辰才算八字；没有时辰，就计算三柱，界面直接显示「六字」。

少两个字，就是少两个字的信息量。
不把不确定，包装成确定。

光也随姿态而动

玻璃面板的光影方向跟随设备姿态。传感器把倾斜方向映射成光照向量，再分层绘制色晕、高光、斜纹与轮廓。

为了照顾弱芯片，高光中心移动不到半个像素就不重建。人眼分辨不了的位移，不必付出计算开销。
